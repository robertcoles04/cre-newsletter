# CRE Blurb Phase 1 (MVP) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A pipeline, run each morning by GitHub Actions, that collects CRE news, rates, Fed odds and REIT quotes, then has Claude draft the day's issue. Code fills every number, and the draft is delivered as a Markdown file plus a GitHub Issue.

**Architecture:** Plain Python modules form a linear pipeline: collect → store/dedupe (SQLite) → classify (Claude) → fact sheet → chart → draft (Claude) → checks → editor pass (Claude) → fill numbers → deliver. Claude runs through the `claude -p` CLI, authenticated with `CLAUDE_CODE_OAUTH_TOKEN` (Max subscription). Every network and Claude call is injectable, so tests run offline.

**Tech Stack:**
- Python 3.12 (Actions) and 3.14 (local)
- httpx, feedparser, PyYAML, rapidfuzz, matplotlib, python-dotenv
- pytest, respx
- SQLite (stdlib)
- `gh` CLI
- Claude Code CLI

**Spec:** `docs/superpowers/specs/2026-10-04-cre-newsletter-design.md`

## Global Constraints

- The model never writes a rate, bps change, price or set of odds. Every number in the issue comes from a `{{PLACEHOLDER}}` filled by `src/fill.py`. A missing value renders as `n/a`, never a guess.
- The pipeline only saves drafts (a repo file plus a GitHub Issue). It never publishes to Substack or emails subscribers.
- Every Top Stories and Quick Hits item links to its source URL.
- Footer on every issue, verbatim: `For informational purposes only. Not investment advice.`
- Word budgets:

  | Issue / section | Words |
  |---|---|
  | Mon–Thu issue | ~1,100 |
  | Fri issue | ~1,100 |
  | Sat issue | ~500 |
  | Sun issue | ~500 |
  | The Numbers | ~100 |
  | Debt Markets | ~200 |
  | Top Stories | ~500 |
  | Quick Hits | ~100 |
  | Term of the Day | ~50 |

- Top Stories count: 3–5 Mon–Thu, 2–3 Fri. Quick Hits count: 5–8, weekdays only.
- Blocked outlets (therealdeal.com, globest.com, multihousingnews.com, cpexecutive.com) come only via Google News `site:` queries. They contribute the headline and public summary only.
- Secrets come from env vars only: `FRED_API_KEY`, `ALPHA_VANTAGE_API_KEY`, `CLAUDE_CODE_OAUTH_TOKEN`, `GH_TOKEN`. `.env` is loaded locally, and `.env` and `*.db` are never committed.
- Time zone: all "today" logic uses `America/New_York`.
- HTTP calls send a browser User-Agent, use timeout=30s, and retry twice.

## Review Focus

1. **Weekend or holiday with no new FRED value.** The change is computed against the prior *observation*, and the as-of date shows the observation date. It must not show a fake "0 bps" for today. This is tested in Task 4.
2. **Model types a raw number** (e.g. "the 10Y hit 4.6%"). `check_issue` must flag it as `model_number`. Tested in Task 9.
3. **Alpha Vantage returns its rate-limit JSON** (`"Note"` or `"Information"` key, no quote). This counts as a failed source, not a $0 price. Tested in Task 6.
4. **The workflow runs twice on the same day** (DST double trigger or a manual rerun). Delivery is idempotent: one file per date, and no second GitHub Issue. Tested in Task 11.
5. **Feed item with no date, or a date in the future.** No date → skip. Future date → clamp to now. A malformed feed must not crash the run. Tested in Task 3.

### Task 2: SQLite store and dedupe

**Files:**
- Create: `src/store.py`, `tests/test_store.py`

**Interfaces:**
- Consumes: `Item`, `RatePoint`, `ReitQuote` (Task 1)
- Produces:
  - `connect(path: str) -> sqlite3.Connection`. Creates these tables if missing:
    - `items(id INTEGER PK, source, url, canonical_url UNIQUE, title, published_at TEXT ISO, summary, priority INT, cluster_id INT, also_covered TEXT JSON list, section, asset_class, market, importance INT, used_in_issue TEXT)`
    - `deals` (per spec §6; unused until Phase 2)
    - `rates(series, date, value, PK(series,date))`
    - `reit_quotes(ticker, date, close, change_pct, PK(ticker,date))`
    - `issues(date PK, day_type, status, markdown, source_problems TEXT, term TEXT, gh_issue INT)`
  - `canonical_url(url: str) -> str`:
    - lowercases the host
    - drops the scheme, `www.`, query params starting `utm_`, `oc`, `ref`, the fragment, and the trailing `/`
  - `normalize_title(title: str) -> str`: strips a trailing `" - <Source>"` (Google News style), lowercases, collapses whitespace
  - `save_items(conn, items: list[Item]) -> int`: returns the number of new clusters. Dedupe rules:
    - An exact `canonical_url` match is ignored.
    - Otherwise, if `rapidfuzz.fuzz.token_set_ratio(normalize_title(a), normalize_title(b)) >= 85` against any item published within 48h, it joins that item's cluster.
    - The cluster's representative is the highest `priority`. Other sources' names are appended to the representative's `also_covered`.
  - `save_rates(conn, points)`, `save_quotes(conn, quotes)`
  - `get_rates(conn, series, since: date) -> list[RatePoint]`, sorted by date
  - `recent_items(conn, since: datetime) -> list[sqlite3.Row]`: representatives only

### Task 9: Templates, draft, checks, editor pass, fill

**Files:**
- Create:
  - `templates/weekday.md`, `templates/friday.md`, `templates/saturday.md`, `templates/sunday.md`
  - `config/voice.md`, `config/banned_phrases.txt`
  - `src/draft.py`, `src/checks.py`, `src/fill.py`
  - `tests/test_draft_checks_fill.py`

**Interfaces:**
- Consumes: `run_claude`, `MODEL_WRITE`, the fact sheet dict
- Produces:
  - `draft.write(factsheet, run=run_claude) -> str`
    - The prompt is: `config/voice.md` + the template for `day_type` + the fact sheet as JSON (with `values` replaced by the list of placeholder names only, so the model never sees the numbers).
    - The prompt also includes these rules:
      - Use `{{NAME}}` for every number from `values`.
      - Write no other numeric rates, percentages, prices, odds or bps.
      - Link each story with `[source](url)`.
      - Respect the word budgets.
      - End with the footer.
  - `draft.edit(md, factsheet, run=run_claude) -> str`. This is the editor pass: cut vague or unsupported lines, keep placeholders and links unchanged, mark doubtful claims `[CHECK]`, and return the full Markdown.
  - `checks.check_issue(md, factsheet, banned: list[str]) -> list[dict]`. Each problem is `{kind, detail}`. The kinds are:
    - `banned`: a banned phrase was found (case-insensitive)
    - `em_dash`: more than 2 `—`
    - `exclaim`: any `!` outside URLs
    - `long_sentence`: over 30 words
    - `budget`: a `##` section over 130% of its budget
