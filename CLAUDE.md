# cre-newsletter

CRE Blurb: daily commercial real estate (CRE) newsletter published as a GitHub Pages website (auto-published when the draft passes the publish gate, else approved via an `approved` label on the draft Issue). A scheduled Python pipeline collects news + data, Claude drafts the issue, it goes live automatically if it passes the gate, and Robert (the owner, the user) reviews after publication. Full original spec: `BRIEF.md`. Design spec: `docs/superpowers/specs/2026-10-04-cre-newsletter-design.md`.

## Status
Phase 1 is merged (pending secrets + first scheduled run). Website publishing is built (GitHub Pages, workflow `.github/workflows/publish.yml`), pending going public + enabling Pages. Auto-publish (2026-10-06): after daily.yml commits issues/ it runs `gh workflow run publish.yml -f issue=<N>` (Issue number from the pipeline's `issue` step output); a dispatch with `issue` behaves like the `approved` label (gate, record, deploy, comment "Published automatically", close). Gate failure comments "Not auto-published: <reasons>" and leaves the Issue open for the manual label. A push to main touching `issues/*.md` or `issues/*.json` only rebuilds + deploys (no gate, no recording); site.py skips failing dates with a `::warning::`. Bot pushes use GITHUB_TOKEN, which starts no workflows (why the label cannot be added by the bot). Phase 1 = MVP (feeds + FRED + Polymarket + REIT strip -> SQLite -> Claude draft -> GitHub Issue delivery). Workflow: `.github/workflows/daily.yml` (cron 09:07 + 10:07 UTC plus backups at 09:13/09:43/10:13/10:43/11:13/11:43 UTC because GitHub starts scheduled runs hours late; the 5 AM-5:59 PM ET gate + already-delivered check keep one issue a day; DB kept on the `data` branch).

## Commands
- Setup: `python -m venv .venv && .venv/Scripts/python -m pip install -r requirements.txt`; copy `.env.example` to `.env`.
- Test: `.venv/Scripts/python -m pytest`
- Local run: `.venv/Scripts/python -m src.main --force --dry-run` (flags: `--date`, `--dry-run`, `--force`, `--db`)
- CI: `gh workflow run daily.yml -f force=true`, then `gh run watch`.

## Decisions so far (override BRIEF.md where they differ)
- Runs 7 days: Mon-Fri detailed (~1,000 words), Sat/Sun lighter (~500).
- Sections (match `templates/`): every day opens with The Brief (3 bullets, ~15 words each, no numbers, each ending with its story link). Mon-Thu: The Numbers (+ REIT movers, Chart of the Day), Debt Markets (+ Distress Watch), Top Stories (+ 2 or 3 "Coffee chat talking points"), Market Watch, Quick Hits (max 6), AI in Real Estate (heading becomes "AI Infrastructure" when the story is data centers/power/chips; only when real news), Term of the Day. Fri: same plus Deals of the Week. Sat: Week in Review, Market Spotlight (one metro or property type from the week's stories), AI in RE Weekly, Term of the Day. Sun: REIT Weekly, Week Ahead, Careers Corner (one practical tip, no numbers), Term of the Day. The site renders a Data Room block after Term of the Day.
- Everything free for now; no paid tier.
- Runtime: Python on GitHub Actions cron; Claude steps via Claude Code headless on Robert's Max subscription (CLAUDE_CODE_OAUTH_TOKEN), no API key.
- Blocked feeds (The Real Deal, GlobeSt, Multi-Housing News, CPE, CoStar) -> Google News `site:` queries, headline only. Never bypass bot protection.
- No X via browser cookies; no LinkedIn scraping. Gmail ingestion deferred.
- Market Summary (2026-10-05): adds 2Y, 10Y-2Y curve (shown in bps), 30Y mortgage, and a Credit group (now rendered as the Data Room, see Reader review below: HY OAS, bank CRE loans `CREACBW027SBOG`, bank CRE delinquency `DRCRELEXFACBS`, Trepp CMBS delinquency parsed from its monthly headline in `src/trepp.py`). Weekly/quarterly series use longer FRED windows (`rates.SERIES_LOOKBACK_DAYS`) and show an as-of in the row label. Every row has a gray hint (`render_html.HINTS`). Fed odds are split into cut/hold/hike. No "Sources" caption. REIT movers show company names (`reit_info` in sources.yaml) and a code-picked "why it moved" story or a code-filled "no company-specific news" note.
- Week Ahead (Sunday) merges the Fed calendar JSON with FRED `releases/dates` (free, existing key) filtered to a major-release allowlist (`calendar.MAJOR_RELEASES`: CPI, jobs, GDP, PCE, retail sales, PPI, JOLTS, housing starts, construction spending, new/existing home sales, ECI), code-filled via `{{WEEK_AHEAD}}`. FRED gives no times. No Alpha Vantage earnings calendar (would eat the ~25/day quota). BLS `bls.ics` returns 403 to our descriptive User-Agent (not worked around); Census's indicator RSS lists only past releases. Both skipped.
- Market Watch (weekdays, after Top Stories): one story each for Sun Belt / West Coast / International, picked in code (`src/markets.py`) by keyword region match or the regional Google News query tag, never a story already used above. PERE and React News `site:` queries returned nothing, so they are not used.
- Style: no em or en dashes anywhere. Prompts forbid them, `checks` flags any, and `render_html.no_dashes()` replaces them at render time. Quick Hits = news line + link + ONE plain explanation sentence; AI section favors tools/use cases over data centers.
- Editions: Mon-Fri "Daily Edition", Sat/Sun "Weekend Edition", plus "N min read" (words/230). Sheet width 860px (was 760 before the 2026-10-05 polish pass).
- Reader review (2026-10-05): tone is "plain English for a smart college student new to CRE", never babyish. 10Y `move_size` (unchanged < 3 bps, small 3-9, notable >= 10) scales "What it means". Fed Funds row = target range (FRED DFEDTARL/DFEDTARU, DFF fallback). Rates rows show their own "(as of ...)" when not RATES_ASOF's day. Credit rows moved to a "Data Room" block after Term of the Day with an "Updated" tag (as-of within 7 days). Stock/REIT recap stories older than 24h are dropped; `checks` adds a `contradiction` editor note when prose says REITs fell/rose against VNQ_CHG's sign. Politically charged government deals (ICE detention, prisons) are kept out of Top Stories when other stories exist. Story source names go through `source_names` in sources.yaml. Site: RSS `feed.xml` (20 newest), About page "How each issue is made" + "Corrections", Recent issues list only from 3 issues. Not done: decoding Google News links (unreliable, no official API).
- UX + charts pass (2026-10-05): `src/chart.py` draws 5 optional charts (10Y, yield curve incl. DGS30, 30Y mortgage 26 weeks, Fed odds bar, REIT scoreboard from `factsheet["reit_moves"]`, kept out of the model's sheet); full-width ones also get a `-sm` phone version via `<picture>`. Delivery copies them to `issues/img/<date>-<name>.png` and records alt/size in the JSON's `charts`; the site copies them next to each issue. Pages have authored SVG heading icons, an "In this issue" jump list, prev/next issue links, skip link, aria-current nav. See DESIGN.md.
- UI polish pass (2026-10-05): bigger reading type (body 18px / 1.65, h2 1.9rem), 860px sheet with 48px padding, cover tagline, The Brief as a navy-wash panel, Coffee chat line as a serif italic pull quote, muted "Why it matters:" lead-ins, Market Watch bullets rendered as paragraphs (template + prompt now ask for a paragraph + "Why it matters:"), uppercase group labels with a gold rule, larger on-chart text and no chart border. Sizes in DESIGN.md.

- Critique fixes (2026-10-06, `.impeccable/critique/`): the 10Y-2Y curve is computed in code from the 10Y and 2Y on the same date (`factsheet.same_date_curve`; FRED T10Y2Y only as fallback) and Treasury.gov also fills DGS2/DGS30; the yield-curve chart uses the latest common date and its key names it ("Oct 5"). New editor-note checks: `curve_mismatch`, `repeat_in_issue` (a URL linked 3+ times, or in Debt Markets and Distress Watch), `coffee_chat`, `big_move_ignored` (fact sheet `big_movers` = rates rows that moved 15+ bps). Distress Watch uses a code-picked `distress` story never in Debt Markets/Top Stories (null = omit the line). Page order: Brief, 3-row Market Snapshot, jump list, stories, full Market Summary, Term, Data Room. Rates/Fed/Data Room change marks are navy (color only for prices). Site writes favicon.svg, robots.txt, sitemap.xml; archive shows each issue's top headline. Old issues keep their single Coffee chat line (renderer handles both).

- Broadsheet redesign (2026-10-06): newspaper look from an approved mockup (DESIGN.md). Libre Caslon Display / Source Serif 4 / Public Sans, white paper + ink, navy CSS ticker code-filled from fact-sheet values (no JS, reduced-motion safe), masthead on every page with nav Today / Markets / Archive / Glossary / About, 12-col grid on desktop (lead story + Brief, Snapshot strip, story grid, Coffee chat band, paired sections that stack when unbalanced, The Numbers at `#numbers`, Term + Data Room). New `/glossary/` page built from published issues' Term of the Day.

- Legal + accessibility (2026-10-06): `/privacy/`, `/terms/`, `/accessibility/` pages (`site.INFO_PAGES`, in the sitemap), footer row About / Privacy / Terms / Accessibility on every page, a no-JS Pause/Play checkbox on the ticker, fonts self-hosted from `fonts/` (OFL; only the private preview links Google Fonts). Anonymity: the site and prompts never name the owner; contact is corrections@creblurb.org (`site.CONTACT_EMAIL`); a test fails if any built page contains "Robert" or "icloud". WCAG 2.1 AA pass (axe-core: 0 violations at 1280px, 375px, reduced motion): masthead h1 on issue pages, DOM order Brief, Snapshot, lead, `--gold-text`, h3 group names, list roles, fact-sheet chart alt, sr-only n/a text; see DESIGN.md.
- Data freshness (2026-10-06): Polymarket odds only from the market whose endDate (ET) is the `config/fomc.yaml` meeting day (or the next morning before noon), open and unresolved; else n/a + "polymarket: no market for <meeting>". `FED_ASOF` (run date ET) goes in the Fed chart caption. REIT quotes must be dated `freshness.previous_trading_day(run_date)` (Mon-Fri minus NYSE holidays in `freshness.MARKET_HOLIDAYS`, update yearly), or the run date when the run starts after 4:30 PM ET; one trading day per issue (`reits.split_stale`). Stale = dropped + "reits: <T> quote is stale (<date>)", never retried. `REIT_ASOF` labels the REIT rows' hints (when it differs from RATES_ASOF), the scoreboard caption and alt. Reruns reuse stored quotes (+ the VNQ yield, kept in `rates` as series `VNQ_YIELD`) for that trading day when most tickers have one: no Alpha Vantage calls. Repaired: 2026-10-06 curve (one date, Oct 5) and scoreboard (no stale AVB); 2026-10-05 json has `REIT_ASOF: Oct 2`.
- Two sources per number (2026-10-06): REIT/VNQ prices come from free sources first (`src/collect/prices.py`: Tiingo when TIINGO_API_KEY is set; Stooq is coded but off, `reit_stooq: false`, because it serves a JavaScript bot check). Alpha Vantage confirms VNQ + 3 date-rotated REITs (`reits.confirm_set`) and fills gaps, so it uses ~5 calls/day (all tickers only when no free source is up). `prices.cross_check`: within 0.5% agree; a third source breaks ties; disagreement without a tiebreaker = n/a + note; one source = published + "single source" note (only when a second source was expected). DGS2/5/10/30: FRED vs Treasury.gov on the latest common date (`rates.cross_check_treasury`), >2 bps = Treasury.gov wins + note. SOFR stays FRED only (NY Fed dropped by Robert). Fed odds: Kalshi series KXFEDDECISION (no key or account for reads) shown as "Kalshi: hold X%" under the odds rows (`KALSHI_HOLD`); hold gap >10 pts = note; Polymarket stays primary. Provenance: factsheet/json `sources` per value; code-built `DATA_CHECKS` line ends the Data Room (kept out of the model's placeholders). Disagreements are banner notes, never a gate block. `reit_quotes.source` column stores provenance for same-day reruns.

## Guardrails (non-negotiable)
- The daily run auto-publishes issues that pass the publish gate; failing drafts wait for the approved label. Only publish.yml puts an issue on the website (after the gate); nothing is emailed.
- Rates, bps changes, REIT prices: inserted by code from APIs, never written by the model.
- Deal numbers must appear in source text, else blank or `[CHECK]`.
- Summarize in our own words, link every claim, max one short quote per source.
- Secrets in `.env` only (see `.env.example`). Never commit keys or the SQLite DB.
- Ask Robert before adding any paid service or API.
